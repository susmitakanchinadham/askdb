Slice 4: Planner with fake LLM client, first end-to-end ask

Added
- src/askdb/llm.py: LLMClient protocol (text in, text out), FakeLLMClient (queued replies, records
  prompts), AnthropicClient (stdlib urllib, key from ANTHROPIC_API_KEY, model claude-sonnet-5-5 or
  ASKDB_MODEL), LLMUnavailable for any outage/credential/parse failure.
- src/askdb/prompts.py: system prompt (rules, reply shapes, allowed functions, today, glossary text)
  and user prompt (question, prior interpretations, validator code+message on retry).
- src/askdb/planner.py: Planner.plan -> Answer | Clarify | Refuse | Unavailable. One retry on a
  validator rejection or malformed reply; second failure -> Refuse("validation_failed"); an
  outage returns Unavailable immediately with no retry.
- src/askdb/api/ask.py + main.create_app(llm=...): POST /ask. Responses never contain the statement.
  Without ANTHROPIC_API_KEY the app answers with the friendly outage message.
- Fix found by the golden run: executor.ordered_sql left statements with their own LIMIT unchanged
  (added tie-break keys changed which rows top-N kept). Unit test added.
- Tests: tests/unit/test_planner.py, tests/integration/test_ask.py, tests/validation/test_golden.py,
  tests/validation/recorded/*.json (28 cases).
